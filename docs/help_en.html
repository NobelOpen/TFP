TaskFlow Help

v1.0

Overview

TaskFlow is a visual task automation tool that lets you build automation workflows by dragging and configuring task cards. Each task card represents a single operation step, executed in sequence from top to bottom.

Core Concepts

Flow: An ordered sequence of task cards executed from top to bottom. You can create multiple flows and switch between them using the tab bar on the left.

Task Card: Represents a specific operation. Right-click on the canvas to add a task card; double-click or right-click to edit its properties.

Variable: Data is passed between tasks via variables. To reference another card's output in a property field, use the #{card number} syntax.

Expression: Some properties support expressions using the {{expression}} syntax, e.g. {{#1.x + 10}}.

Output Reference Syntax

Subsequent cards can reference the outputs of preceding cards using the following syntax (N is the card number):

#N.image Image · #N.text Text · #N.x / #N.y Coordinates · #N.result Boolean result · #N.loopIndex Loop index

Interface Guide

Main Toolbar

The toolbar at the top of the main window contains all the core control functions of the application:

New / Open / Save / Save As
Manage project files (.json). Contains all flows, cards, local variables, and UI layout states.
🔽 Hide Main Window
Click to completely hide the software's main window, bringing up a compact Real-time Task Overlay Window. How to Restore: You can also look for the TaskFlow icon in the System Tray (bottom-right of the Windows taskbar) and double-click it to show the main window again.
🪟 Real-time Task Overlay
A mini floating card that appears after hiding the main window. This overlay is always on top, making it perfect for monitoring task progress while AFK:
• Drag to Move: Click and hold anywhere on the window background to easily drag it to any position on the screen.
• Double-Click Restore: Double-click anywhere on the window background to instantly restore the main window.
• Smart Opacity: When a flow is actively running, moving your mouse away from the window makes the task area semi-transparent (50% opacity) so it doesn't block your view limitlessly. Hovering over it restores full visibility.
• Controls: Quickly switch flows (↻), run current flow (▶), run all flows (▶▶), stop execution (⏹), and restore the main window with one click (◉). The switch flow button spins during execution, and color changes indicate the active state.
• Progress Context: Highlights the name of the currently executing task card in real-time, displaying its breadcrumb context (e.g., inside an If-branch or For-loop). It also fades the previous and next card names, giving you a clear view of the execution progress at a glance.
⚙ Settings
Open the system settings window (Shortcut: F12).
📦 Variables
Open the variable management window to configure global variables and local variables for the selected flow.
📑 Flows
Open the flow management window to create, rename, or delete different task flows.
📱 Models
Open the model management window to configure LLM API parameters for text translation and multimodal vision.
👁 Vision Models
Open the vision model management window. Use this to explicitly load, hot-swap, or remove local ONNX object detection weight files from memory buffers.
❓ Help
Open the built-in offline task flow instruction manual in a local browser.
▷ Run Once / Run Current / Run All
Run Once: Executes only the currently selected card once (useful for debugging).
Run Current: Executes all tasks in the currently active flow tab.
Run All: Executes all tasks across all flow tabs in sequence.
⏹ Stop All
Forcefully interrupts all currently running flows.
🤖 AI Assistant
Toggle the left-side AI Flow Assistant panel. See the AI Flow Assistant section for details.
Image Preview / Live View / Log Output
Toggle the visibility of different panels at the bottom or sides.

Variable Manager

Accessed via the ｛｝ Variables button. Variables are used to dynamically store data or share states between multiple cards.

Variable Scope
Divided into Global Variables and Local Variables specific to a Flow. Local variables take precedence when names conflict.
Data Types
Currently supports Int (Integer), Double (Float), String, and Bool (Boolean).
How to Reference
Wherever cards support expressions, use @VariableName to read from or write/overwrite variables. Example: @Count = @Count + 1.

Flow Manager

Opened via the Flows button. TaskFlow allows creating multiple flows within a project (vertical tabs on the left) to break down complex logic.

Basic Operations
Add new flows, rename, or delete. Note: Deleting a flow will also delete all task cards and local variables within it. This action cannot be undone.
Minimum Requirement
At least one flow must be kept. You can rename the last remaining flow, but cannot delete it.

Model Manager

Configure API endpoints required to call LLM (Large Language Model) services. Used for AI cards like LLM Translate, Multimodal Vision, and LLM File Translation. Open via the 📱 Models button in the toolbar.

Model List
The top of the window shows a model list table displaying all configured models. Each row shows: Display Name (user-defined identifier), API Endpoint, Model Name, and Token Stats (cumulative Input and Output token consumption). Model configurations take effect globally on the local machine (not project-specific). Once configured, they can be reused across any project.
Add Model
Click the Add Model button at the bottom to open the edit dialog, fill in the parameters, and save. Note: Display names must be unique (case-insensitive).
Edit Model
Select a row and click Edit Model to modify parameters in the edit dialog. Canceling discards all changes. When editing, keeping the original display name will not trigger a duplicate name error.
Delete Model
Select a row and click Delete Model. After confirmation, the model configuration is permanently removed. This action cannot be undone.
Core Parameters
Display Name: A user-defined identifier for the model, used to distinguish models when selecting them in AI cards. Must be unique and non-empty.
API Endpoint: The full API request URL. Three formats are supported:
• OpenAI Chat Completions (default): e.g., https://api.openai.com/v1/chat/completions or https://api.deepseek.com/chat/completions
• OpenAI Responses API: endpoints containing /v1/responses in the URL
• Google Gemini API: e.g., https://generativelanguage.googleapis.com/v1beta/ — the program automatically appends models/{modelName}:generateContent
API Key: The key provided by the service. OpenAI-compatible services use Bearer Token authentication; Gemini API uses the X-goog-api-key header — the program handles this automatically.
Model Name: The actual model name required by the backend, e.g., gpt-4o, deepseek-chat, gemini-2.0-flash. For Gemini API, there's no need to include :generateContent in the model name (it will be auto-stripped if accidentally included).
Timeout (seconds): Maximum wait time for API calls, default 60 seconds. Increase this value for slower models or larger requests.
Test Connection
Select a model and click Test Connection. The program sends a minimal chat request to verify API connectivity and key validity. The window is temporarily disabled during testing. On success, the HTTP status code and a response summary are shown; on failure, the error code and detailed error message are displayed for troubleshooting.
Reset Stats
Select a model and click Reset Stats to zero out the cumulative Input Token and Output Token counts for that model.
Token Stats
The Token Stats column in the list shows real-time cumulative consumption for each model, formatted as "Total N (In: X Out: Y)". This helps you track API usage and costs per model. Counts are automatically incremented after each successful AI card invocation.
Configuration Examples
OpenAI / DeepSeek: API Endpoint = https://api.deepseek.com/chat/completions, API Key = sk-xxxx, Model Name = deepseek-chat
Google Gemini: API Endpoint = https://generativelanguage.googleapis.com/v1beta/, API Key = AIzaSy..., Model Name = gemini-2.0-flash
Self-hosted / Proxy: API Endpoint = https://your-proxy.com/v1/chat/completions, API Key = as required by the provider

Vision Model Manager

Manages ONNX Runtime-based local vision inference models, specifically designed for image object detection and localization tasks. Open via the 🧿 Vision button in the toolbar.

Applicable Scenarios
Currently primarily loads exported ONNX format YOLO object detection models (e.g., YOLOv8). Since the model infers strictly locally on the CPU, lightweight models (like Nano or Small variants, e.g., yolov8n.onnx) are recommended to ensure fast execution speeds. Unlike expensive cloud-based Large Vision Models (LlmVision), local ONNX models are perfectly suited for high-frequency, real-time, low-latency coordinate positioning tasks.
Model List
Displays all imported vision models centrally. Configuration parameters are securely saved locally for cross-project invocation.
Import Model
Click the Import button at the top right to select a .onnx model file from your local disk. The system will automatically copy and isolate it in the application's dedicated data directory (%LOCALAPPDATA%/TaskFlow/onnx_models/). The underlying layer natively supports dynamic input dimension processing.
Edit Model Parameters
To ensure optimal inference speed and accuracy, each model usually requires tuning its preprocessing configuration and post-processing thresholds:
Display Name: A custom name for easy identification in the task card's dropdown menu.
Input Width / Height: The required input image tensor size. Often 640x640. Set appropriately to avoid severe aspect ratio distortion.
Default Confidence: The base confidence filtering threshold applied to model output (0~1, e.g. 0.4). Bounding boxes scoring below this value are discarded.
Labels List: Comma-separated target class names (e.g., person,car,dog). Ensure the order strictly aligns with the category index (0, 1, 2...) set during model training. This is crucial when cards utilize "Class Filter" capabilities. If left empty, the system outputs bounding boxes but cannot filter by class names.
Delete Model
Clicking the Delete button securely removes both the configuration and the underlying .onnx physical file from the storage directory. Note that deleting a model currently referenced by a card will cause errors in the flow.

Settings & OCR

Configure software startup behaviors, task execution logic, and engine paths.

Startup Behavior
Supports setting: Auto start with Windows, auto load the last used project, run all flows immediately after startup, and hide the main window on startup (run entirely in the background). Essential for long-term unattended automation.
Execution & Loop
Flow Interval: Global delay added between the sequential execution of multiple cards.
Repeat Run All: When checked, after all flows finish running once, the app waits for a specified interval and reruns from the beginning, achieving infinite looping.
WeChat OCR Configuration
TaskFlow supports calling the extremely fast and highly accurate WeChat OCR engine component. Under OCR Settings, click Auto Detect. If WeChat has been logged in on the machine, it can usually auto-find the required file paths. Otherwise, manually specify WeChatOCR.exe and its corresponding WeChatXX.X.X runtime directory. Click "Test Availability" to verify.

AI Flow Assistant AI

The AI Flow Assistant can automatically design and create complete task card workflows based on your natural language descriptions. Click the 🤖 AI Assistant button in the toolbar to expand the left panel.

How to Use
1. Select Model: Choose a configured LLM model from the dropdown at the top of the panel (must be added in Model Manager first).
2. Describe Requirements: Type your automation needs in natural language, e.g., "Launch Chrome, take a screenshot, then use OCR to recognize text".
3. Review Plan: The AI generates a plan with concrete steps, displayed in a tree structure (with indentation for If-Else branches and For loops).
4. Confirm Creation: Click "Confirm" to have the AI automatically create all task cards; or click "Regenerate" to have the AI redesign the plan.
5. Fill Properties: After creation, the panel shows a report of properties that need manual input. Click any report item to jump directly to that card's property dialog.
Control Flow Support
The AI can generate nested workflows with If-Else conditional branches and For loops. For example, describing "if the screenshot matches a button then click it, otherwise pause and retry" will automatically create the corresponding IfElse branch structure.
Flow Context Awareness
The AI assistant automatically detects existing task cards on the canvas. When cards are already present, you can:
• Analyze / Review: Type "analyze the current flow" or "check for issues" and the AI will read the existing card structure and provide analysis.
• Explain: Type "explain what this flow does" and the AI will describe the flow's functionality in natural language.
• Append: Type "add OCR recognition at the end" and the AI will only generate new steps (without duplicating existing cards).
Visual Intuition (Direct Screenshot)
When you ask the AI about screen content (e.g., "what icons are on the desktop?"), or ask it to perform operations requiring visual context, if there is no preceding screenshot card, Orchid will automatically capture a full-screen screenshot in the background and send it to the LLM. Therefore, you do not need to manually instruct it to "take a screenshot first"—it inherently "sees" your screen, perfectly suited for pure analysis or coordinate querying. Note that to avoid resource conflicts, the "Live Preview" feature is temporarily disabled while Orchid is analyzing.
Smart Card Insertion
Orchid can intelligently insert newly generated task cards into existing complex logic branches. For example, if you want to add steps inside an existing If-Else branch or a For loop, simply instruct "insert a click task into #4's IF branch". Orchid uses nested block structures to precisely insert cards at the correct level, without needing to rebuild the entire control flow block. This makes local modifications to complex flows extremely convenient.
Two-Stage LLM Calls
To optimize token consumption, the AI uses a two-stage approach: Stage 1 determines which card categories are relevant to the request; Stage 2 loads only the detailed descriptions of those categories to generate the plan. This significantly reduces token usage per request.
Automatic Variable Creation
When a flow requires counters, status flags, or loop conditions, the AI automatically declares required variables in the plan (supporting Int, String, Bool, and Double types). Upon confirmation, variables are automatically added to the Variable Manager—no manual creation needed. You can see declared variables marked with 📦 in the plan preview.
Enhanced Property References
The AI can use @variableName to reference variables, and #N.propertyName to reference outputs from previous steps. For example, the AI may generate #2.path to reference a file path found in step 2, or use @retryCount to reference a retry counter variable.
Logging
All AI Flow Assistant interactions are automatically saved to local log files in the logs/ai_flow/ folder under the program directory, named by date (e.g., ai_flow_2026-03-15.log). Logs contain: user input, LLM request/response JSON, token consumption, card creation details, and exception stack traces. When encountering issues, simply provide the corresponding date's log file to the developer for quick troubleshooting.
Usage Examples
Simple linear flow: "Launch Notepad, take a screenshot, then use OCR to recognize text"
Conditional branch flow: "After taking a screenshot, match a button template. If matched, click it; otherwise, pause 1 second and retry"
Loop flow: "Repeat 5 times: take a screenshot and OCR recognize, break the loop if it contains 'Done'"
Analyze existing flow: "Analyze the current flow for any issues"
Append steps: "Add a subtitle notification step at the end of the current flow"
General Tasks

Pause All Tasks General

Pauses flow execution for the specified number of milliseconds. Commonly used to wait for page loads, animations, etc.

Delay (ms)
Number of milliseconds to pause. Supports expressions. For example, 1000 pauses for 1 second.
Output
No output (controls flow pause only)

Get Timestamp General

Gets the current system time and outputs a formatted string.

Format String
C# date format, e.g. yyyy-MM-dd HH:mm:ss, yyyyMMdd.
Output
#N.text — Current time (formatted string based on the output format)

End Current Flow General

Immediately terminates execution of the current flow without affecting other flows.

Output
No output (controls flow termination only)

End All Flows General

Immediately terminates execution of all flows.

Output
No output (controls flow termination only)

Restart Flow General

Immediately terminates current flow and restarts execution from the beginning.

Output
No output (controls flow reset only)
Windows Operations

Win Launch App Windows

Launches a specified Windows application. You can specify launch arguments and working directory.

Application Path
Full path to the executable, e.g. C:\Windows\notepad.exe.
Launch Arguments
Optional command-line arguments passed to the application.
Examples
App path C:\Program Files\Google\Chrome\Application\chrome.exe
Arguments https://www.google.com → Launches Chrome and opens the URL
Arguments --incognito https://www.google.com → Opens in incognito mode
Output
No output (launches the application only)

Win Screenshot Windows

Captures a screenshot of a specified process window. Supports automatic grayscale conversion.

Process Name
Target window's process name without the .exe suffix. E.g. notepad, chrome.
Include Title Bar
Whether to include the window title bar area. Enabled by default. Uncheck to exclude the title bar region.
Top Crop Height
Custom pixel height to crop from the top of the window, useful for removing custom title bars. Default 0.
Convert to Grayscale
When checked, the screenshot is automatically converted to grayscale. Grayscale images reduce data size and improve processing speed and accuracy for template matching and OCR, while reducing color interference.
Output
#N.image — Captured window image (color or grayscale)

Win Simulate Click Windows

Simulates a mouse click at specified coordinates within a process window (uses Windows message mechanism, does not move the actual mouse cursor).

X Coordinate Expression / Y Coordinate Expression
Coordinates within the window. Supports numbers, @variables, #task references, and expressions.
Click Type
Single Click: sends one click; Double Click: enables multiple clicks with customizable count and interval; Swipe: swipes from start to end coordinates with configurable duration.
Swipe Duration
Duration of the swipe operation (milliseconds), default 300ms. Only visible when click type is Swipe.
Background Click
When checked, sends background messages via PostMessage to the target process without requiring the window to be in the foreground. Requires specifying the target process name. Works when the window is occluded or minimized.
Examples
Fixed coordinate click: X = 100, Y = 200
Reference template match output: X = {{#3.x}}, Y = {{#3.y}} (#3 is the template match card number)
Offset click: X = {{#3.x + 50}}, Y = {{#3.y - 10}}
Output
#N.x — Actual click X coordinate
#N.y — Actual click Y coordinate

Win Close App Windows

Closes the application window with the specified process name.

Process Name
Name of the process to close.
Output
No output (closes the application only)

Win UI Automation Windows

Uses the Windows UI Automation framework to operate UI elements. Can find controls by name or AutomationId and perform click, input, and other actions. (Features a built-in element inspector via right-click)

Process Name
Target window's process name.
Search By
By control Name or by AutomationId.
Match Mode
Exact match / Contains / Regular expression.
Examples
Find button by name: Search By = Name, Match Mode = Contains, Search Text = OK
Find by AutomationId: Search By = AutomationId, Match Mode = Exact, Search Text = btnSubmit
Regex match: Match Mode = Regex, Search Text = ^(OK|Save)$ (matches controls named "OK" or "Save")
Regex wildcards: btn.*Submit (matches names starting with btn and ending with Submit), \d+ (matches names containing digits)
Output
#N.text — Text content of the element (if applicable)

Win Simulate Input Windows

Simulates keyboard key presses or mouse wheel operations with modifier key combinations. Useful for automating shortcuts, scrolling pages, etc.

Modifier Keys
Optional modifier key combinations: None, Ctrl, Shift, Alt, Ctrl+Shift, Ctrl+Alt.
Input Action
Mouse Wheel Down: simulates scrolling down; Mouse Wheel Up: simulates scrolling up; Keyboard Key: simulates a specific key press.
Key Name
Only shown when input action is "Keyboard Key". Enter the key name, e.g. A, ENTER, TAB, ESCAPE, F5.
Scroll Amount
Only shown for mouse wheel actions. Default 120 (one standard scroll step).
Repeat Count
Total number of times to perform this action, default 1.
Repeat Interval (ms)
Wait time between each repetition, default 50ms.
Examples
Ctrl+S Save: Modifier = Ctrl, Action = Keyboard Key, Key = S
Scroll down 5 times: Action = Mouse Wheel Down, Repeat = 5, Interval = 200
Press Enter: Modifier = None, Key = ENTER
Output
#N.text — Description of the action performed

Win Subtitle Overlay Windows

Overlays subtitles on a specified process window. Useful for displaying translation results. Supports custom font, color, and background styles.

Display Text Expression
Text to display. Supports expressions. Can reference translation results like {{#5.text}}.
Target Window
When checked, subtitles are displayed on the specified process window; when unchecked, absolute screen coordinates are used.
Process Name
Target window for subtitle overlay (shown when "Target Window" is checked).
Select Display Region
Click to automatically capture the target process window, then select a rectangular region on the screenshot as the subtitle display area. Automatically fills in X/Y offset and width/height. Avoids manual coordinate calculation.
X / Y Offset
Offset relative to the target window's top-left corner. Can be automatically filled by region selection.
Subtitle Width / Height
Subtitle area dimensions. 0 = auto-fit to text.
Font Size / Font Color
Subtitle text size and color (hex, e.g. #000000). Color picker available for quick selection.
Background Style
Frosted Glass: semi-transparent acrylic effect; Solid Color: solid color fill; Transparent: no background; Auto Color Sample: automatically samples the average background color of the target area for a blended look.
Background Color
Color value with transparency, e.g. #80FFFFFF. Only shown in Frosted Glass/Solid Color modes. Color picker available.
Display Duration
Duration to show subtitles (milliseconds). 0 = persistent until next update.
Wait for subtitle to close before continuing
When checked, the flow waits until the subtitle display duration ends before executing the next task.
Examples
Display static text: Subtitle content = Processing...
Display translation result: Subtitle content = {{#5.text}} (#5 is the LLM translation card)
Concatenate multiple variables: Subtitle content = Original: {{#3.text}} → Translation: {{#5.text}}
Output
No output (displays subtitle overlay only)

Win Path Finder Windows

Searches for a target file within a specified directory (or across all local drives) and returns the absolute path of the first match found.

File Name to Find
The name of the target file, e.g., Code.exe or photo.jpg. Supports expressions.
Search Root Path
The starting directory path for the search. Leave empty to search across all local logical drives.
Max Search Depth
Limits the level of recursive directory traversal. 0 means unlimited, 1 means searching only in the root directory without entering subfolders.
Enable Wildcard Matching
When checked, allows wildcard symbols like *.exe or report_?.pdf (case-insensitive by default). Uncheck for exact name matching.
Examples
Search across all drives: File Name = WeChat.exe, Search Root Path is left empty.
Wildcard search in specific folder: File Name = screenshot_*.png, Root Path = D:\Images, Checked Wildcard.
Output
#N.Found Path — Full absolute path of the first matching file (alias for #N.OutputFilePath)
#N.result — Whether the file was found successfully (True/False)

Win Text Input Windows

Inputs a complete block of text at once. Supports character-by-character simulation and clipboard pasting.

Input Text
The text to input. Supports @variables and #task references.
Input Mode
Char-by-Char: simulates keyboard input for each character (useful for anti-injection fields); Clipboard Paste: copies text to clipboard and simulates Ctrl+V (faster).
Char Interval
Interval (ms) between each character in character-by-character mode, default 50ms.
Output
No output

Win Input Combo Windows

Supports multi-key orchestration (mix of tap and hold) with non-blocking background execution. Often used for gaming or complex application macros.

Key List
Add multiple key actions (e.g., W, A, Space, LeftClick). Each action can be set to Tap or Hold with dedicated post-action delay. Held keys remain pressed until the task card ends.
Repeat Count
Number of times the action sequence repeats. Set to 0 for infinite loop (requires a stop condition).
Stop Expression
Evaluated after each cycle (stops execution if false). Default true.
Max Duration
In milliseconds (0 = unlimited). Timeout forces termination and releases all held keys.
Output
#N.text — Records the key combos and status info for this execution

Win Event Listener Windows

Continuously wait for a specific keyboard or mouse event, such as executing subsequent tasks when a shortcut key is pressed.

Event to Listen
Select the key or mouse action to listen for.
Output
#N.result — Returns true when the event is triggered

Image Processing

Image Crop Image

Crops a specified region from the source image.

Source Image
Reference the output image from a preceding screenshot card, e.g. #1 (card number).
Crop Region X / Y / Width / Height
Top-left corner coordinates and dimensions of the crop rectangle. Supports expressions.
Output
#N.image — Cropped image

Template Match Image

Searches for a template image within the source image. Supports single and multi-target matching.

Source Image
The target image to search in. Reference a preceding screenshot card.
Template Image
The small image to find. Loaded from file.
Match Threshold
Value between 0–1. Higher values require stricter matches. Typically set to 0.8–0.95.
Max Match Count
1 = single target match; >1 = multi-target match.
Examples
Find button position: Threshold = 0.85, use If to check #N.result, then click at #N.x, #N.y
Multi-target match: Max count = 5, results accessible via OutputMatchResults array
Threshold guidelines: Identical icons 0.9–0.95, similar elements 0.75–0.85, fuzzy match 0.6–0.75
Output
#N.image — Result image with match positions annotated
#N.result — Whether a match was found (true/false)
#N.x / #N.y — Center coordinates of the best match (single target)
OutputMatchScore — Best match score (0–1)
OutputMatchCount — Number of matches found
OutputMatchResults — Multi-target match result list (with X, Y, Score)

ONNX Detect Image

Performs real-time object detection and localization tracking on images using a local ONNX vision model (e.g., YOLO).

Source Image
The target image source, usually referenced from a preceding screenshot card (e.g., #1) or a crop card output.
Vision Model Selection
Select the specific model to use from the dropdown menu, populated by models imported via the "Vision Model Manager".
Class Filter (Comma-separated)
Optional. Enter specific target label names you want to filter. For instance, if your model detects both cats and dogs, but you only want dog coordinates, type dog here. Leave empty to output all detected objects that meet the confidence threshold.
Confidence Override
Optional. A decimal value between 0 and 1 (e.g., 0.65) to temporarily override the model's default confidence threshold. Lower this value if the model is missing detections; raise it if there are too many false positives. Use 0 to retain the model's default setting defined in the Manager.
Application Scenarios
When dealing with changing lighting conditions, minor icon deformations, or partial occlusions, traditional "Template Match" often fails. In these cases, deploying deep learning-based ONNX object detection models provides highly robust crosshair positioning and dynamic coordinate acquisition.
Output
#N.image — Highlit preview image with colored bounding boxes and confidence scores drawn for all valid detections.
#N.result — Whether at least one required target was detected (true/false).

TaskFlowPro API Guide
1. Reading/Writing Task Outputs and Properties
• TaskFlowPro.GetTool("#N TaskName.Property"): Gets a task card's value. Examples:
var text = TaskFlowPro.GetTool("#1 Image Crop.text")?.ToString();
var x = Convert.ToInt32(TaskFlowPro.GetTool("#2 Get Coord.X"));

• TaskFlowPro.SetTool("#N TaskName.Property", value): Dynamically sets a writable property of a subsequent task.
2. Reading/Writing Global and Local Variables
• TaskFlowPro.GetVar("@VarName"): Reads a variable. Example:
int count = Convert.ToInt32(TaskFlowPro.GetVar("@Counter"));

TaskFlowPro.SetVar("@Counter", count + 1);

using var img = TaskFlowPro.GetImage("#3 Screenshot");

• TaskFlowPro.SetOutputText(string): Set text output.

• Console.WriteLine("...") or TaskFlowPro.Log("..."): Prints debugging information to the script editor's output console panel and the flow execution logs.
