TaskFlow 帮助文档

v1.0

概述

TaskFlow 是一个可视化的任务自动化工具，通过拖拽和配置任务卡片来构建自动化流程。每个任务卡片代表一个操作步骤，按顺序执行。

基本概念

流程（Flow）：一组有序排列的任务卡片，从上到下依次执行。可以创建多个流程，通过左侧标签栏切换。

任务卡片（Task Card）：代表一个具体操作。右键点击空白区域可添加任务卡片，双击或右键编辑属性。

变量（Variable）：任务之间的数据通过变量传递。在属性中引用其他卡片的输出时，使用 #{卡片序号} 语法。

表达式（Expression）：部分属性支持表达式，使用 {{表达式}} 语法，如 {{#1.x + 10}}。

输出引用语法

后续卡片可通过以下语法引用前序卡片的输出（N 为卡片序号）：

#N.image 图像 · #N.text 文本 · #N.x / #N.y 坐标 · #N.result 布尔结果 · #N.loopIndex 循环索引

界面功能指南

主窗口工具栏

主窗口顶部的工具栏包含了应用所有的核心控制功能：

新建 / 打开 / 保存 / 另存为
管理工程文件 (.json)。包含所有的流程、卡片、局部变量以及界面布局状态。
🔽 隐藏主窗口
点击后彻底隐藏软件主窗口，并在屏幕上弹出一个精简的实时任务悬浮窗。如何彻底恢复：您也可以在 Windows 桌面右下角的系统托盘区找到 TaskFlow 图标，双击图标即可重新显示主窗口。
🪟 实时任务悬浮窗
隐藏主窗口后出现的迷你悬浮卡片。此悬浮窗会始终置顶显示，适合在挂机时随时监控任务进度：
• 自由拖拽：按住窗口背景的任意位置即可将其轻松拖拽至屏幕的任意角落。
• 双击恢复：在窗口背景空白处双击鼠标左键，即可一键恢复显示主窗口。
• 智能透明度：当任务正在运行时，鼠标移出悬浮窗范围，任务区域会自动变为半透明（50%透明度），避免过度遮挡屏幕视线；鼠标悬停时则恢复不透明。
• 控制区：支持快速切换流程 (↻)、运行当前流程 (▶)、运行全部 (▶▶)、停止执行 (⏹) 以及恢复主窗口 (◉)。运行中切换按钮会无限旋转，且停止图标颜色加深以示提醒。
• 进度与上下文：实时高亮显示当前执行的任务，并在需要时显示其所在层级上下文（如位于哪个 For 循环或 If 分支内）。同时淡化显示上一步与下一步任务名称，让流程进度一目了然。
⚙ 设置
打开系统设置窗口（快捷键 F12）。
📦 变量
打开变量管理窗口。用于配置当前工程内的全局变量，和所选流程的局部变量。
📑 流程
打开流程管理窗口。可创建、重命名、删除不同的任务流程（Flow）。
📱 模型
打开模型管理窗口。配置用于文本翻译、多模态识图的 LLM 接口参数。
▷ 单步运行 / 运行当前 / 运行全部
单步运行：仅运行当前选中的那张卡片一次（便于调试）；
运行当前：运行当前激活的流程页签内的所有任务；
运行全部：按顺序依次运行所有流程页签内的任务。
⏹ 停止全部
强制中断当前正在运行的所有流程。
✦ Orchid
切换左侧 AI 流程助手面板的显示/隐藏。详细说明请参阅 AI 流程助手 章节。
图像预览 / 实时预览 / 日志输出
控制底部或侧边不同面板的显示与隐藏。

变量管理

通过工具栏的 ｛｝ 变量 按钮进入。变量用于动态存储数据或在多个卡片之间共享状态。

变量层级
分为 全局变量 和针对某一个 Flow 的 流程局部变量。同名时局部变量优先。
数据类型
当前支持 Int (整数)、Double (浮点数)、String (字符串)、Bool (布尔) 四种。
如何引用
在卡片支持输入表达式的地方（或赋值表达式卡片内），使用 @变量名 来读取或覆盖写入。如：@Count = @Count + 1。

流程管理

点击工具栏 � 流程 按钮打开。TaskFlow 允许在一个工程里创建多条流程（即主界面左侧的垂直页签），以拆分复杂的逻辑。

基础操作
可以添加新流程、重命名、删除。请注意：删除流程将会一并删除该流程内的所有任务卡片及其下属的局部变量，此操作不可撤销。
至少保留一个
必须保留至少一个流程，不可将流程全部删空。可以修改最后一条流程的名称，但不能将其删除。

模型管理

配置调用 LLM（大语言模型）服务需要的 API 端点。用于支持 LLM翻译、多模态识图、LLM文件翻译 等人工智能卡片。通过工具栏的 📱 模型 按钮打开。

模型列表
窗口上方为模型列表表格，展示所有已配置的模型。每行显示：显示名称（用户自定义的标识）、API Endpoint、Model Name、Token 统计（累计消耗的 Input 和 Output Token 数量）。模型配置是针对本地计算机全局生效的（非当前工程独有），配置一次以后任何工程均可复用。
添加模型
点击底部 添加模型 按钮，打开编辑对话框填写以下信息后保存即可。注意：显示名称不允许与已有模型重复（不区分大小写）。
修改模型
选中某行后点击 修改模型 按钮，在编辑对话框中修改参数。取消则放弃所有修改。编辑时保留原始显示名称不会被判为重复。
删除模型
选中某行后点击 删除模型 按钮，确认后永久移除该模型配置。此操作不可撤销。
核心参数
显示名称：用户自定义的模型标识名称，用于在 AI 卡片中选择模型时区分。必须唯一且不能为空。
API Endpoint：完整的 API 请求地址。支持以下三种格式：
• OpenAI Chat Completions（默认）：如 https://api.openai.com/v1/chat/completions 或 https://api.deepseek.com/chat/completions
• OpenAI Responses API：URL 中包含 /v1/responses 的端点
• Google Gemini API：如 https://generativelanguage.googleapis.com/v1beta/，程序会自动拼接 models/{模型名}:generateContent 路径
API Key：提供商发放的密钥。OpenAI 系使用 Bearer Token 认证；Gemini API 使用 X-goog-api-key 头认证，程序会自动处理。
实际模型名（Model Name）：后端要求传入的模型名称，如 gpt-4o、deepseek-chat、gemini-2.0-flash。对于 Gemini API，无需在模型名中包含 :generateContent 后缀（如误填也会自动去除）。
超时时间（秒）：API 调用的最大等待时间，默认 60 秒。对于较慢的模型或较大的请求，可适当增加该值。
测试连接
选中模型后点击 测试连接 按钮，程序将自动发起一个极简对话请求以验证 API 连通性及密钥有效性。测试期间窗口将暂时禁用交互。测试成功后显示 HTTP 状态码和响应摘要；失败则显示错误码与详细错误信息，便于排查。
重置统计
选中模型后点击 重置统计 按钮，将该模型累计的 Input Token 和 Output Token 计数清零。
Token 统计
列表中的 Token 统计 列实时展示每个模型的累计消耗。格式为「共 N (入:X 出:Y)」，方便您跟踪各模型的 API 用量和成本。每次成功调用 AI 卡片后自动累加。
配置示例
OpenAI / DeepSeek：API Endpoint = https://api.deepseek.com/chat/completions，API Key = sk-xxxx，Model Name = deepseek-chat
Google Gemini：API Endpoint = https://generativelanguage.googleapis.com/v1beta/，API Key = AIzaSy...，Model Name = gemini-2.0-flash
自建/中转服务：API Endpoint = https://your-proxy.com/v1/chat/completions，API Key = 按服务商要求填写

常用设置与OCR

在此处可以配置软件启动行为、任务执行逻辑与引擎路径等。

启动行为
支持设置：开机自动启动、启动时自动加载上一次最后使用的工程文件、启动后立即开始执行全部流程、启动时隐藏主窗口（完全在后台运行）。这对于长期无人值守运行的自动化非常重要。
执行与循环
流程间隔：在连续执行多张卡片之间可全局增加的延时；
循环运行全部：打勾后，当所有流程全部跑完一遍后，等待指定间隔，再次从头跑，实现无限挂机。
微信 OCR 配置
TaskFlow 支持调用提取极速、高准确率的微信 OCR 引擎组件。在设置的OCR 设置部分，点击 自动检测，若本机已登录过微信，通常能自动找齐所需的文件路径。也可以手动指定 WeChatOCR.exe 以及其所对应的 WeChatXX.X.X 运行时运行目录。配置完成可以点击“测试可用性”验证。

✦ Orchid AI

AI 流程助手可以根据您的自然语言描述，自动设计并创建完整的任务卡片流程。点击工具栏的 ✦ Orchid 按钮即可展开左侧面板。

使用流程
1. 选择模型：在面板顶部的下拉框中选取已配置的 LLM 模型（需先在模型管理中添加）。
2. 描述需求：在输入框中用自然语言描述您想实现的自动化流程，如"启动谷歌浏览器，截图，然后用 OCR 识别文字"。
3. 查看方案：AI 会生成包含具体步骤的方案，以树状结构展示（支持 If-Else 分支和 For 循环的缩进显示）。
4. 确认创建：确认方案无误后点击「确认创建」，AI 将自动创建所有任务卡片；也可点击「重新生成」让 AI 重新设计。
5. 完善属性：创建完成后，面板会显示需要手动填写的属性报告，点击报告项可直接跳转到对应卡片的属性对话框。
控制流支持
AI 可以生成包含 If-Else 条件分支 和 For 循环 的嵌套流程。例如描述"如果截图匹配到按钮则点击，否则暂停重试"，AI 会自动创建对应的 IfElse 分支结构。
流程感知
AI 助手能够自动感知当前画布上已有的任务卡片。当画布上已有卡片时，您可以：
• 分析/审查：输入"分析一下当前流程"或"检查有没有问题"，AI 会解读现有卡片结构并给出分析。
• 解释流程：输入"解释一下这个流程做了什么"，AI 会用自然语言描述流程的功能。
• 续编追加：输入"在末尾加上 OCR 识别"，AI 会只生成新增的步骤（不重复已有卡片）。
视觉直觉（直接获取屏幕）
当您向 AI 提问屏幕内容（如“桌面上有哪些图标”），或让其执行需要视觉上下文的操作时，如果当前流程中没有前序的截图卡片，Orchid 会自动在后台捕获当前全屏截图并发送给大模型。因此，您无需手动要求它“先截图”或在对话中显式提及截图，它天生就能“看到”您的屏幕情况，非常适合执行纯分析或坐标查询。同时为了避免冲突，Orchid 思考时会自动禁用“实时显示”功能。
智能卡片插入
Orchid 能够智能地将新生成的任务卡片插入到现有的复杂逻辑流中。例如，如果您想在现有的 If-Else 分支 或 For 循环 内部添加步骤，只需输入如“在 #4 的 If 分支里插入一个点击任务”，Orchid 会使用嵌套的卡片结构精准地将卡片插入到对应层级，而无需重建整个控制流块。这极大方便了复杂流程的局部修改。
两阶段调用
为优化 Token 消耗，AI 采用两阶段调用：第一阶段判断需求涉及哪些卡片类别；第二阶段仅加载相关类别的详细描述来生成方案。这大幅减少了每次请求的 Token 用量。
自动创建变量
当流程需要计数器、状态标记或循环条件时，AI 会在方案中自动声明所需变量（类型支持 Int、String、Bool、Double）。确认创建时，变量会被自动添加到变量管理器中，无需手动创建。在方案预览中可以看到 📦 标记的变量列表。
属性引用增强
AI 能够使用 @变量名 引用变量，#N.属性名 引用前序步骤的输出。例如 AI 可能生成 #2.path 来引用第 2 步查找到的文件路径，或使用 @retryCount 引用重试计数器变量。
日志记录
AI 流程助手的所有交互记录会自动保存到本地日志文件中，位于程序目录下的 logs/ai_flow/ 文件夹，按日期命名（如 ai_flow_2026-03-15.log）。日志包含：用户输入、LLM 请求/响应 JSON、Token 消耗、卡片创建过程、异常堆栈等完整信息。遇到问题时，将对应日期的日志文件提供给开发者即可快速定位问题。
用法示例
简单线性流程："启动记事本，截图，然后用 OCR 识别文字"
条件分支流程："截图后模板匹配按钮，如果匹配到则点击，否则暂停1秒后重试"
循环流程："循环5次：截图并 OCR 识别，如果包含'完成'则中止循环"
分析现有流程："分析一下当前流程有没有问题"
续编追加："在当前流程末尾加上一个字幕提示步骤"
通用任务

暂停全部任务 通用

暂停流程执行指定的毫秒数。常用于等待页面加载、动画完成等场景。

延迟时间 (ms)
暂停的毫秒数，支持表达式。例如 1000 表示暂停1秒。
输出
无输出（仅控制流程暂停）

获取当前时间 通用

获取当前系统时间，输出格式化字符串。

格式化字符串
C# 日期格式，如 yyyy-MM-dd HH:mm:ss、yyyyMMdd。
输出
#N.当前时间 — 当前时间（int 类型时间戳，格式由输出格式决定）

结束当前流程 通用

立即终止当前流程的执行，不影响其他流程。

输出
无输出（仅控制流程终止）

结束全部流程 通用

立即终止所有流程的执行。

输出
无输出（仅控制流程终止）
Windows 操作

Win启动应用 Windows

启动指定的 Windows 应用程序。可指定启动参数和工作目录。

应用路径
可执行文件的完整路径，如 C:\Windows\notepad.exe。
启动参数
可选，传递给应用程序的命令行参数。
示例
应用路径 C:\Program Files\Google\Chrome\Application\chrome.exe
启动参数 https://www.google.com → 启动 Chrome 并直接打开该网址
启动参数 --incognito https://www.google.com → 以无痕模式打开网址
输出
无输出（仅启动应用程序）

Win截屏工具 Windows

截取指定进程窗口的屏幕图像。支持截取后自动转为灰度图。

进程名称
目标窗口的进程名，不需要 .exe 后缀。例如 notepad、chrome。
包含标题栏
是否包含窗口标题栏区域，默认包含。取消勾选可去除标题栏区域。
顶部裁剪高度
自定义裁剪窗口顶部的像素高度，用于去除自定义标题栏。默认 0。
转换为灰度图像
勾选后截屏结果自动转为灰度图。灰度图可减少数据量、提高模板匹配和 OCR 的处理速度与准确率，并降低颜色干扰。
输出
#N.image — 截取的窗口图像（彩色或灰度）

Win模拟点击 Windows

在指定进程窗口的指定坐标位置模拟鼠标点击（使用 Windows 消息机制，不移动实际鼠标）。

X坐标表达式 / Y坐标表达式
窗口内的坐标，支持数字、@变量、#任务引用 和表达式。
点击类型
单击：仅发送一次点击；双击：可启用多次点击，自定义点击次数和间隔；滑动：从起点坐标滑动到终点坐标，可设置滑动时长。
滑动时长
滑动操作的持续时间（毫秒），默认 300ms。仅在点击类型为滑动时显示。
离屏点击
勾选后通过 PostMessage 向目标进程发送后台消息，无需窗口在前台显示。需指定目标进程名称。适用于窗口被遮挡或最小化的场景。
示例
固定坐标点击：X = 100，Y = 200
引用模板匹配输出坐标：X = {{#3.x}}，Y = {{#3.y}}（#3 为模板匹配卡片序号）
偏移点击：X = {{#3.x + 50}}，Y = {{#3.y - 10}}
输出
#N.x — 实际点击的 X 坐标
#N.y — 实际点击的 Y 坐标

Win关闭应用 Windows

关闭指定进程名的应用程序窗口。

进程名称
要关闭的进程名。
输出
无输出（仅关闭应用）

WinUI自动化 Windows

使用 Windows UI Automation 框架操作 UI 元素。可以按名称或 AutomationId 查找控件并执行点击、输入等操作。

进程名称
目标窗口的进程名。
查找方式
按控件名称（Name）或按 AutomationId 查找。
匹配模式
精确匹配 / 包含匹配 / 正则表达式。
示例
按名称查找按钮：查找方式 = Name，匹配模式 = 包含匹配，搜索内容 = 确定
按 AutomationId 精确定位：查找方式 = AutomationId，匹配模式 = 精确匹配，搜索内容 = btnSubmit

在模型管理中配置的 LLM 模型。
输入文件路径
待翻译文件路径（支持变量）。
输出文件路径
翻译结果保存路径（支持变量）。
目标语言
翻译目标语言，默认“简体中文”。
系统提示词
自定义翻译规则。翻译时会保持行数一致，且保留角色名等。
每批最大字符数
单次请求分段的最大字符数，用于超大文件自动切块。
输出
OutputTranslatedFilePath — 已翻译文件的输出路径
控制流

If-Else分支 控制流

根据条件判断执行不同的分支。支持多个 Elif 分支和可选的 Else 分支。

条件来源
手动输入表达式 或 引用其他卡片的执行结果（Result）。
条件表达式
返回布尔值的表达式，如 #1.result == true。
示例
判断模板匹配结果：条件来源 = TaskResult，引用模板匹配卡片 → 匹配成功执行 If 分支，失败走 Else
手动条件：条件来源 = ManualInput，表达式 = #3.text == "确认"
多条件分支：If + Elif + Else 实现三路以上分支判断
输出
无直接输出（控制执行路径）

提示：右键点击 IF 开始卡片可以增加 Elif 分支或显示/隐藏 Else 分支。折叠按钮（▶）可以折叠整个分支块。

For循环 控制流

重复执行循环体内的任务卡片指定次数。

循环次数
要执行的总次数，支持表达式。
示例
固定次数循环：循环次数 = 10 → 重复执行 10 次
遍历 Blob 结果：循环次数 = {{#5.blobCount}}，循环体内用数组解析 + 索引 {{#N.loopIndex}} 逐个处理
配合 Break：在循环体内用 If 判断条件，满足时中止循环
输出
#N.loopIndex — 当前循环索引（从 0 开始）

提示：在循环体内可使用 #N.loopIndex 引用当前循环索引（N 为循环开始卡片的序号）。

中止循环 控制流

立即跳出最近的 For 循环，继续执行循环后面的任务。通常与 If 条件配合使用。

输出
无输出（仅控制循环跳出）
